# Viper Package Manager (vpm)

The Viper Package Manager (`vpm`) is the built-in package management system for Viper projects. It allows you to manage dependencies, publish packages, and organize your Viper projects.

## Quick Start

### Initialize a New Package

```bash
# Initialize a new Viper package
viper vpm init my_project
cd my_project

# Project structure created:
# my_project/
# ├── vpm.toml       # Package manifest
# ├── .gitignore
# └── src/
#     └── main.vp    # Main source file
```

### Add Dependencies

```bash
# Add a registry dependency (version constraint)
viper vpm add requests

# Add a specific version
viper vpm add requests@1.2.0

# Add a Git dependency
viper vpm add mylib --git https://github.com/user/mylib

# Add a Git dependency with specific branch
viper vpm add mylib --git https://github.com/user/mylib --branch develop

# Add a local path dependency
viper vpm add mylib --path ../mylib
```

### Install Dependencies

```bash
# Install all dependencies from vpm.toml
viper vpm install

# Install a specific dependency
viper vpm install requests
```

### Manage Dependencies

```bash
# List installed packages
viper vpm list

# Show dependency tree
viper vpm tree

# Remove a dependency
viper vpm remove requests

# Update dependencies
viper vpm update

# Update a specific package
viper vpm update requests
```

### Search and Discover

```bash
# Search for packages
viper vpm search json

# Show package information
viper vpm show requests
```

### Publish Your Package

```bash
# Bump patch version and publish
viper vpm publish --bump patch

# Bump minor version
viper vpm publish --bump minor

# Bump major version
viper vpm publish --bump major

# Dry run (no changes made)
viper vpm publish --bump patch --dry-run
```

### Maintenance

```bash
# Clean package cache
viper vpm clean
```

## The vpm.toml Format

The `vpm.toml` file is the manifest for your Viper package. Here's an example:

```toml
[package]
name = "my_package"
version = "1.0.0"
edition = "2021"
authors = ["Your Name <you@example.com>"]
description = "A wonderful Viper package"
license = "MIT"
repository = "https://github.com/username/my_package"
documentation = "https://docs.example.com"
homepage = "https://example.com"

# Dependencies
[dependencies]
# Registry dependency with version constraint
requests = ">=1.0"

# Exact version
json-parser = "2.3.4"

# Git dependency
mylib = { git = "https://github.com/user/mylib", branch = "main" }

# Path dependency (local development)
local-lib = { path = "../local-lib", version = "1.0.0" }

# Git dependency with tag
utils = { git = "https://github.com/user/utils", branch = "v1.2.0" }

# Development dependencies (for testing)
[dev-dependencies]
test-framework = ">=1.0"

# Build dependencies
[build-dependencies]
build-helper = ">=0.5"

# Feature flags
[features]
default = ["async"]
async = []
database = ["sqlite"]
full = ["async", "database"]
```

## Version Specification

Viper uses semantic versioning (SemVer). You can specify versions in several ways:

| Format | Example | Meaning |
|--------|---------|---------|
| Exact | `"1.2.3"` | Exactly version 1.2.3 |
| Minimum | `">=1.0"` | Version 1.0 or higher |
| Range | `">=1.0, <2.0"` | Version 1.0 or higher, but less than 2.0 |
| Caret | `"^1.2.3"` | Compatible with 1.2.3 (≥1.2.3, <2.0.0) |
| Tilde | `"~1.2.3"` | Approximately 1.2.3 (≥1.2.3, <1.3.0) |
| Wildcard | `"1.*"` | Any 1.x.x version |

## Project Structure

A typical Viper project with vpm:

```
my_project/
├── vpm.toml          # Package manifest (required)
├── vpm.lock          # Lock file (generated, commit to VCS)
├── .gitignore
├── src/
│   ├── main.vp       # Main entry point
│   └── lib.vp        # Library code
├── tests/
│   └── test_main.vp
├── benchmarks/
│   └── bench_main.vp
├── docs/
│   └── README.md
└── vendor/           # Downloaded dependencies (git-ignored)
    ├── requests/
    └── json-parser/
```

## Workspace Support

For multi-package projects, you can use workspaces:

```toml
[workspace]
members = [
    "core",
    "utils",
    "cli"
]
```

## Features

Features allow optional dependencies and conditional compilation:

```toml
[features]
# Default features enabled for all users
default = ["async", "logging"]

# Optional features
async = ["asyncio"]
logging = ["log"]
database = ["sqlite", "orm"]

# Feature with dependencies
full = ["async", "logging", "database"]
```

Enable features when building:

```bash
viper build --features database src/main.vp
```

## Dependency Resolution

vpm uses a dependency resolution algorithm to ensure all dependencies are compatible:

1. Reads `vpm.toml` and `vpm.lock` (if present)
2. Resolves version constraints
3. Downloads packages to `vendor/` directory
4. Generates `vpm.lock` with exact versions

## Lock File

The `vpm.lock` file contains the exact versions of all dependencies. Commit this file to version control to ensure reproducible builds.

```toml
# Auto-generated by vpm - commit this file
[[package]]
name = "requests"
version = "1.2.3"
source = "registry"

[[package]]
name = "mylib"
version = "0.5.0"
source = "git+https://github.com/user/mylib?branch=main#abc123"
```

## Best Practices

1. **Commit `vpm.lock`**: Always commit the lock file to ensure reproducible builds across environments.

2. **Use semantic versioning**: Follow SemVer for your package versions.

3. **Pin versions in libraries**: Library packages should use exact versions or narrow ranges.

4. **Use ranges in applications**: Application packages can use wider version ranges.

5. **Vendor Git dependencies**: Git dependencies are cloned to `vendor/` for offline builds.

6. **Document features**: Clearly document which features are available and what they enable.

## Troubleshooting

### Dependency Resolution Fails

If vpm can't resolve dependencies:

```bash
# Clear cache and retry
viper vpm clean
viper vpm install

# Check for version conflicts
viper vpm tree
```

### Update Issues

If updates break your build:

```bash
# Update one package at a time
viper vpm update requests

# Check what changed
viper vpm show requests
```

| `viper vpm install [pkg]` | Install dependencies |
